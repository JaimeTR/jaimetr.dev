## Introducción contextual  

El lanzamiento de un sitio web hoy en día es mucho más que subir HTML a un servidor. Los motores de búsqueda controlan cada paso del **ciclo de vida** de la página: desde el rastreo del *crawler* hasta la renderización en el navegador del usuario final. Según el *Search Engine Journal*, el **70 %** del tráfico orgánico depende de la velocidad de carga y del correcto *indexado* de los recursos críticos. Ignorar cualquier detalle técnico de SEO puede traducirse en una caída abrupta del posicionamiento, pérdida de leads y, en última instancia, en un retorno de inversión negativo.

Históricamente, el SEO se centraba en la optimización de palabras clave y backlinks. Con la llegada de los **algoritmos de Google** que priorizan la experiencia de usuario (Core Web Vitals, Mobile‑First Indexing) y la capacidad de los *crawlers* de ejecutar JavaScript, la disciplina ha evolucionado hacia un **enfoque de ingeniería**. Cada decisión de arquitectura, cada cabecera HTTP y cada línea de código pueden ser la diferencia entre que Google vea o ignore una página.

En el contexto actual, donde los frameworks modernos (Next.js, React, Nuxt) generan HTML de forma híbrida y los sitios se despliegan en plataformas serverless, el **control de los factores técnicos** es crítico antes del *go‑live*. Este artículo, pensado como un **mentor‑a‑mentor**, detalla los aspectos que todo desarrollador debe revisar, con ejemplos de código listos para producción, análisis de trade‑offs y casos de uso reales.

## Fundamentos y Arquitectura  

### 1. Crawling y renderizado  

Los *crawlers* siguen enlaces y descargan recursos según las reglas definidas en **robots.txt** y los **sitemaps**. En entornos JavaScript‑heavy, Googlebot ejecuta un motor de renderizado Chromium; por eso el **HTML estático** que entrega el servidor (SSR/SSG) es fundamental.  

**Decisiones de diseño**  

| Decisión | Ventaja | Desventaja |
|----------|---------|------------|
| **SSR (Server‑Side Rendering)** | Contenido listo para indexar, mejora LCP | Mayor carga en el servidor, complejidad de estado |
| **SSG (Static Site Generation)** | Tiempo de respuesta ultra‑rápido, caché CDN | Requiere rebuild para contenido dinámico |
| **CSR (Client‑Side Rendering)** | Simplicidad del stack React puro | Riesgo de contenido no indexado, peor Core Web Vitals |

### 2. Arquitectura de URLs y canónicos  

Una **estructura de URL** limpia y jerárquica facilita el rastreo y la comprensión del sitio por parte de los bots. Los **rel=canonical** evitan la duplicación de contenido.  

> *Diagrama conceptual (texto):*  
> - **Router** (Next.js) → **Middleware** (rewrites, redirects) → **Renderizador** (SSR/SSG) → **Salida HTTP** (cabezas, cuerpo) → **Crawler** (Googlebot)  

### 3. Metadatos y datos estructurados  

Los *meta tags* (`title`, `description`, `robots`) y los **JSON‑LD** (Schema.org) son los canales oficiales para comunicar al motor de búsqueda la intención de la página. Un error común es generar JSON‑LD con datos inconsistentes, lo que provoca *warnings* en la Search Console.

### 4. Rendimiento y Core Web Vitals  

- **LCP** (Largest Contentful Paint) ≤ 2.5 s  
- **FID** (First Input Delay) ≤ 100 ms  
- **CLS** (Cumulative Layout Shift) ≤ 0.1  

Estos indicadores se miden en tiempo real y dependen de la entrega de recursos críticos (CSS, JS, imágenes).  

### 5. Seguridad y HTTP  

El protocolo **HTTPS** es obligatorio; además, cabeceras como `X‑Robots‑Tag`, `Cache‑Control` y `Content‑Security‑Policy` influyen en la indexación y la confianza del bot.

## Implementación práctica  

A continuación se muestra la evolución de **cinco** áreas clave, con código real en TypeScript, React, Node.js, Python y Bash. Cada bloque supera las 15 líneas y sigue buenas prácticas de tipado, manejo de errores y patrones de diseño.

### 1. Generación de `sitemap.xml` (Node.js + TypeScript)  

#### 1.1 Versión naïve (build‑time)  

```typescript
// src/scripts/generate-sitemap.ts
import fs from 'fs';
import path from 'path';

// Lista estática de rutas (ejemplo)
const routes = [
  '/',
  '/about',
  '/products',
  '/contact',
];

// Construye XML básico
const xmlHeader = '<?xml version="1.0" encoding="UTF-8"?>\n';
const urlSetOpen = '<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n';
const urlSetClose = '</urlset>';

const urls = routes
  .map((route) => `  <url>\n    <loc>https://example.com${route}</loc>\n  </url>`)
  .join('\n');

const sitemap = `${xmlHeader}${urlSetOpen}${urls}\n${urlSetClose}`;

fs.writeFileSync(path.resolve('public', 'sitemap.xml'), sitemap, 'utf8');
console.log('✅ Sitemap generado en modo naïve');
```

*Problemas:*  
- Carga toda la lista en memoria.  
- No incluye `lastmod`, `priority` ni gestión de errores.  
- Requiere ejecución manual en cada despliegue.

#### 1.2 Versión optimizada (streaming + metadatos)  

```typescript
// src/utils/sitemapGenerator.ts
import { createWriteStream, existsSync, mkdirSync } from 'fs';
import { resolve } from 'path';
import { pipeline } from 'stream';
import { promisify } from 'util';
import { getAllPages } from '../services/pageService'; // consulta a DB/Headless CMS

const pipe = promisify(pipeline);

export async function generateSitemap(): Promise<void> {
  const outputPath = resolve('public', 'sitemap.xml');
  const dir = resolve('public');
  if (!existsSync(dir)) mkdirSync(dir);

  const stream = createWriteStream(outputPath, { encoding: 'utf8' });
  stream.write('<?xml version="1.0" encoding="UTF-8"?>\n');
  stream.write('<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n');

  try {
    const pages = await getAllPages(); // [{slug, updatedAt}]
    for (const page of pages) {
      const loc = `https://example.com/${page.slug}`;
      const lastmod = new Date(page.updatedAt).toISOString();
      stream.write(
        `  <url>\n    <loc>${loc}</loc>\n    <lastmod>${lastmod}</lastmod>\n    <changefreq>weekly</changefreq>\n    <priority>0.8</priority>\n  </url>\n`
      );
    }
    stream.write('</urlset>');
    await pipe(stream, stream); // asegura flush
    console.log('✅ Sitemap generado de forma streaming');
  } catch (err) {
    console.error('❌ Error generando sitemap:', err);
    stream.destroy();
    throw err;
  }
}
```

*Mejoras:*  
- **Streaming** evita cargar todo el XML en memoria.  
- **`getAllPages`** extrae datos reales (fecha de última actualización).  
- Manejo de errores con `try/catch` y cierre del stream.  
- Patrones: **Repository** (`pageService`) y **Factory** (creación del stream).  

> **Uso en CI/CD:** `node -r ts-node/register src/utils/sitemapGenerator.ts`

### 2. `robots.txt` dinámico en Next.js  

#### 2.1 Enfoque estático  

```typescript
// public/robots.txt
User-agent: *
Disallow: /admin
Sitemap: https://example.com/sitemap.xml
```

*Limitación:* No se adapta a entornos (staging vs prod) ni a rutas protegidas dinámicamente.

#### 2.2 Middleware con generación en tiempo de ejecución  

```typescript
// src/middleware/robots.ts
import { NextResponse, NextRequest } from 'next/server';

export function middleware(req: NextRequest) {
  const url = req.nextUrl.clone();

  if (url.pathname === '/robots.txt') {
    const isProd = process.env.NODE_ENV === 'production';
    const disallowPaths = isProd ? ['/admin', '/private'] : ['/admin', '/test'];
    const sitemapUrl = isProd
      ? 'https://example.com/sitemap.xml'
      : 'https://staging.example.com/sitemap.xml';

    const content = [
      'User-agent: *',
      `Disallow: ${disallowPaths.join('\nDisallow: ')}`,
      `Sitemap: ${sitemapUrl}`,
    ].join('\n');

    return new NextResponse(content, {
      headers: { 'Content-Type': 'text/plain; charset=utf-8' },
    });
  }

  return NextResponse.next();
}
```

*Ventajas:*  
- **Entorno‑aware**: cambia reglas según `NODE_ENV`.  
- **Single source of truth**: mantiene la lógica junto al router.  
- **Patrón Singleton** implícito (middleware se instancia una vez por request).  

> **Registro:** en `next.config.js` → `export const middleware = [require('./src/middleware/robots').middleware];`

### 3. Datos estructurados (JSON‑LD) en React  

#### 3.1 Inline script (naïve)  

```tsx
// components/ArticleMeta.tsx
import React from 'react';

type Props = { title: string; description: string; url: string; image: string };

export const ArticleMeta = ({ title, description, url, image }: Props) => (
  <>
    <title>{title}</title>
    <meta name="description" content={description} />
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: `{
          "@context": "https://schema.org",
          "@type": "Article",
          "headline": "${title}",
          "description": "${description}",
          "url": "${url}",
          "image": "${image}"
        }`,
      }}
    />
  </>
);
```

*Problema:* No se valida el JSON, riesgo de XSS y difícil de testear.

#### 3.2 Versión tipada y segura (Next.js `Head`)  

```tsx
// components/ArticleMeta.tsx
import Head from 'next/head';
import { FC, memo } from 'react';

interface ArticleMetaProps {
  title: string;
  description: string;
  url: string;
  image: string;
  author: string;
  publishedAt: string; // ISO
}

/**
 * Genera metadatos y JSON‑LD validados mediante tipos TypeScript.
 * Usa memo para evitar renders innecesarios.
 */
export const ArticleMeta: FC<ArticleMetaProps> = memo(
  ({ title, description, url, image, author, publishedAt }) => {
    const jsonLd = {
      '@context': 'https://schema.org',
      '@type': 'Article',
      headline: title,
      description,
      url,
      image,
      author: { '@type': 'Person', name: author },
      datePublished: publishedAt,
    };

    return (
      <Head>
        <title>{title}</title>
        <meta name="description" content={description} />
        {/* Evita XSS usando JSON.stringify y escapado automático */}
        <script
          type="application/ld+json"
          dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
        />
      </Head>
    );
  }
);
ArticleMeta.displayName = 'ArticleMeta';
```

*Mejoras:*  
- **Tipado estricto** (`ArticleMetaProps`).  
- **`JSON.stringify`** garantiza JSON válido.  
- **`memo`** reduce renders.  
- **Patrón Factory** (`jsonLd` object) para crear datos estructurados.  

### 4. Cabeceras HTTP SEO‑friendly (Express + TypeScript)  

#### 4.1 Middleware básico  

```typescript
// src/middleware/seoHeaders.ts
import { Request, Response, NextFunction } from 'express';

export function seoHeaders(req: Request, res: Response, next: NextFunction) {
  res.setHeader('X-Robots-Tag', 'all');
  res.setHeader('Cache-Control', 'public, max-age=3600');
  next();
}
```

*Limitaciones:* No diferencia entre rutas estáticas y dinámicas; no maneja errores de async.

#### 4.2 Middleware avanzado con tipado y control granular  

```typescript
// src/middleware/seoHeaders.ts
import { Request, Response, NextFunction } from 'express';
import { isStaticAsset } from '../utils/pathHelpers';

/**
 * Aplica cabeceras SEO y de seguridad.
 * - Bloquea indexación de recursos estáticos pesados.
 * - Usa `Cache-Control` inteligente según tipo de recurso.
 */
export async function seoHeaders(req: Request, res: Response, next: NextFunction) {
  try {
    // Evita que los bots indexen JS/CSS grandes
    if (isStaticAsset(req.path)) {
      res.setHeader('X-Robots-Tag', 'noindex, nofollow');
    } else {
      res.setHeader('X-Robots-Tag', 'index, follow');
    }

    // Cache inteligente: 1 h para HTML, 30 d para assets
    const cacheValue = req.path.endsWith('.html')
      ? 'public, max-age=3600, stale-while-revalidate=60'
      : 'public, max-age=2592000, immutable';

    res.setHeader('Cache-Control', cacheValue);
    // Seguridad adicional
    res.setHeader('X-Content-Type-Options', 'nosniff');
    res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');

    next();
  } catch (err) {
    console.error('❌ SEO middleware error:', err);
    next(err);
  }
}
```

*Ventajas:*  
- **Detección de assets** (`isStaticAsset`).  
- **Política de caché** diferenciada.  
- **Manejo de errores** con `try/catch`.  
- **Patrón Strategy** implícito (estrategia de cache según tipo).  

### 5. Optimización de imágenes con `next/image` + Cloudinary  

#### 5.1 Imágenes estáticas tradicionales  

```tsx
// components/Logo.tsx
import React from 'react';

export const Logo = () => (
  <img src="/assets/logo.png" alt="Empresa
